## 정상 요청 하나를 추적하기

키가 들어 있는 터미널 B에서 실행하세요. 응답 헤더의 X-Request-ID를 기록해 둡니다.

```sh
curl -iNsS http://127.0.0.1:8090/chat   -H "Authorization: Bearer $ALICE" -H 'Content-Type: application/json'   -d '{"model":"fast","prompt":"금성을 소개해줘."}'
curl -sS -H "Authorization: Bearer $ALICE" http://127.0.0.1:8090/usage | python -m json.tool
curl -sS -H "Authorization: Bearer $BOB" http://127.0.0.1:8090/usage
```

새 DB라면 Alice에게만 done 한 줄이 보입니다. 요청 ID, 입력 8, 출력 2까지 맞춰 보세요. Bob의 응답은 빈 배열입니다.

## 네 요청을 동시에 보내기

아래를 load.py로 저장하고 `python load.py`를 실행합니다. 결과 출력 순서는 컴퓨터마다 다를 수 있습니다.

```python
import asyncio
import os
import httpx


async def main():
    async with httpx.AsyncClient(base_url="http://127.0.0.1:8090", timeout=180) as client:
        async def ask(number):
            key = os.environ["ALICE" if number % 2 == 0 else "BOB"]
            res = await client.post("/chat", headers={"Authorization": "Bearer " + key},
                                    json={"model": "fast", "prompt": "금성을 한 문장으로 소개해줘."})
            print(number, res.status_code, "[DONE]" in res.text)
        await asyncio.gather(*(ask(i) for i in range(4)))


if __name__ == "__main__":
    asyncio.run(main())
```

연습용 서버에서 네 요청이 겹치면 3개가 200 및 True, 하나가 429 및 False가 됩니다. 사용량에서 각 사용자의 완료 행과 대기 시간을 보세요. 429 요청은 엔진에 들어가기 전에 거절되어 사용 기록에 추가되지 않습니다.

## 장애를 직접 일으켜 확인하기

1. 위 정상 curl에서 유효한 키를 `Bearer bad`로 바꾸면 401, 올바른 키에 모델을 `missing`으로 바꾸면 404가 나옵니다.
2. 정상 요청 명령에 `--max-time 0.5`를 추가하면 답이 오기 전에 클라이언트가 연결을 끊습니다. 잠시 뒤 사용 기록에서 cancelled와 비어 있는 토큰 수를 확인합니다.
3. 터미널 A에서 Ctrl+C로 연습용 엔진을 멈추고 다시 요청합니다. 스트림의 error 이벤트와 기록의 failed를 확인하세요. 서버를 다시 시작하면 다음 요청이 완료돼야 합니다.

응답이 없는 경우 먼저 8091의 연습용 엔진을 직접 호출하고, 그 다음 8090의 게이트웨이를 확인하세요. 두 구간을 나누면 어디서 요청이 멈췄는지 알 수 있습니다.
